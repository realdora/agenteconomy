# Fixed monthly reports

`public/monthly-reports.json` is the append-only catalog served by the dashboard
and read by the apex reports, report hub, footer and sitemap. May 2026 is retained
only as the comparison baseline; published report routes start in June.

The daily data workflow runs `node scripts/reports/publish.mjs` after committing
the new data feed, then commits any new editions. No network/RPC/Dune request is
made by this script. A failure cannot undo the preceding live-feed commit and
is visible as a failed workflow. The dashboard workflow copies the catalog.

New months become eligible eight days after UTC month end. This leaves time for
final daily folds and complete weekly observations. Publishing requires x402
and at least two other protocol families. Individual missing metrics are
disclosed and omitted, never converted to zero. Sparse Tempo dates currently
lack sufficient proof of full-month coverage; do not fill them with zero just
to make this check pass.

Daily metrics require every calendar date, valid nonnegative counts and a source
timestamp after close. Weekly Olas requires each Monday-started week to finish;
it is labeled weeks starting in the month, not calendar-month volume. x402 uses
the closed monthly aggregate and the documented address-coverage boundary.

Existing editions are never regenerated by the scheduled command. Source
commit/hash, observations and comparison denominator/revision are retained.
If last month is corrected, already published growth rates for later months
do not silently change: those editions require their own explicit corrections.

To publish a reviewed correction from already repaired inputs:

```sh
node scripts/reports/publish.mjs --revise 2026-07 --note "Describe the verified source correction and affected metrics."
node --test scripts/reports/snapshots.test.mjs
```

Review the catalog diff before committing. Do not remove prior revisions. The
apex keeps a bundled fallback in `lib/report-snapshot-fallback.json`; copy a
reviewed updated catalog there when making an apex release. A feed outage must
never cause the site to recompute published reports from the rolling daily feed.

Initial restoration on 2026-10-22 corrects July ERC-8004 (101,956) and ACP (7,269),
and August MoM (20.8% and 58.2%). September x402 spans a coverage change, so its
growth rate against August is withheld. Snapshot amounts describe tracked
activity, not a census of all payments or proof of organic commerce.

Usage measurement: `open_dashboard`, `data_access_click`, `citation_copy`,
`chart_interaction`. A click is an intent, not proof of a completed download or
external citation. An active chart pill clicked again produces no new event.
For maintenance/testing, set `localStorage.setItem('ae.analytics.disabled','1')`
then reload, separately on each origin. Remove this item and reload to resume.
This prevents GA and Vercel script loading; it does not retroactively remove data.
